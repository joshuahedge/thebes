## 2. passable and buildable (`src/sim/terrain.js`)

- `buildable(world, i)`: the ground is open land: not `WATER`, not `HILLS`. Terrain only; occupancy, roads and walls stay the caller's checks. Also the test for "dry land off the road net" where a bridge must not count.
- `passable(world, i)`: `buildable(world, i) || (WATER && road[i])` (a bridge). Hills are never passable; roads cannot be laid on hills, so a road tile is always passable.
- `groundRefusal(world, i)`: `null`, `'water'` or `'hills'`. Refusal words: `REASONS.hills` = "Hills: nothing can be built here" (text.js `s47` section at the end; Task 3 owns the hills' other words and may add a ground-chip line).

Routed through them (behaviour unchanged today: no map has hills):
- `sim/commands.js`: `tileReason` (every building, plot and plaza: `checkTiles`, `canPlace`, `conditionsFor`) -> `groundRefusal`; `roadTileReason` -> `groundRefusal` (water still bridgeable); `roadJoins` -> `buildable`.
- `sim/defence.js` `wallTileReason` -> `groundRefusal`.
- `sim/pathfinding.js` `tileCost` (raider flow fields, `ringGoals` in raids.js) -> `passable`.
- `sim/combat.js` `chariotGround` (and `chargeGround` on top of it) -> `passable`.
- `sim/armies.js` `landable` (boat landings) -> `buildable`.
- `sim/wildlife.js` `free` (herd spawn and moves) -> `passable` (herds also keep `groundOk`, desert/rocky only).

## 4. Carts and orders (Tasks 5-6)

Cart: `{ id, from, to, good, amount, len, left, turn, due, state }`.
- `id`: the fetching store's id (one cart per store, so no counter); render ids add Task 6's own base.
- `from`: source store id; `to`: fetching (home) store id.
- `good`, `amount` (units carried; taken from `from` the day it sets out), `len` (road tiles one way when it set out).
- `left` (day set out), `turn` (day it reaches `from`), `due` (day it is home). Integers.
- `state`: `'out'` | `'back'` | `'return'` (`CART_STATES`; `return`: the road broke and the goods go back to the source). Task 5 owns the timing rules; if it needs another state or field it adds it in `s47.js` and says so.

Orders: `b.orders[good] = { fetch }`, absent good = not fetching. Data for trip size, speed and default amount belongs in a Task 5 data block (plan: 20 a trip, 8 road tiles a day, default 100).

## 12. Task 5 additions (storehouse orders and carts, in the sim; binding for Task 6 and later)

Files: `src/sim/carts.js` (all the rules and the functions below), `src/data/s47.js` (`CARTS` { perTrip 20, speed 8, defaultFetch 100 }, `isCart`, `CART_DESTS`, `S47_FIRSTS` `first_cart_trip`, `S47_TIPS` `fetch_far`), `src/ui/text.js` (`S47_CARTS_TEXT`), `src/dev/s47/carts.js` (the `s47-carts` scene and `buildCartsCity`). `cartDay(world, events)` runs in `tickDay` straight after `produceDay`. No random draw is used (ties go to the lower store id), so the carts salt (4709) is still free.

**What an order is.** `b.orders[good] = { fetch }` on a granary or storehouse. The store **fetches** the good up to `fetch` (a whole number 1 to its capacity; default 100). One cart per store: while it is on the road, the store's other orders wait (the one with the biggest share still to fetch goes first). The cart is staffed by the store's own workers: a trip sets out only when the store is working (not paused, not burning, at least a quarter of its workers) and a road touches it. A store without that sends no cart and its status says why (`unstaffed`).

**Source.** The nearest other store, by road distance, that is built to hold the good, is linked to the home by road (any distance, bridges are road) and holds some **above its own fetch order for that good** (`surplusOf`). A store is never drawn below what it fetches itself, so two stores fetching one good never pass it back and forth (a store holding more than its own order may give the excess; one at or under it gives nothing). This reads the plan's "not itself fetching it" and "never below its own fetch order" as one rule. Ties in distance go to the lower id. The source need not be working or staffed (as bazaars restock from any store). A trip carries `min(perTrip, amount still wanted, the source's surplus, the room at home)`; room is the home's capacity less everything it holds.

**Road distance.** `roadLen(world, a, b)`: road tiles from store `a`'s door to store `b`'s along the roads, the first tile counted (two stores beside one road tile are 1 apart); `Infinity` when no road joins them. It is `reachDistance` over `roadReach(world, a, Infinity)`, which `reach.js` already caches per road version, so a day's source searches and cut-road checks add no work until a road changes (tested).

**Timing** (`tripTimes(len, day)`, integers): `turn = day + max(1, ceil(len / speed))`, `due = max(turn + 1, day + ceil(2 * len / speed))`. A cart sets out on the day's work (`left = world.day`), reaches the source on `turn` (state `back`), and is home on `due` (the goods are put down that day; a new cart may set out the same day). The goods leave the source's shelf at set-out.

**When something changes on the way** (checked every day):
- **The road is cut** (home and source no longer linked at all; a longer way round keeps the trip, a road mended before the next day's work changes nothing): the cart turns round, `state: 'return'`, `turn` = the day it was noticed (the break day), `due` = break day + ceil(distance travelled so far on that leg / speed), plus two fields only in this state: `at`, the road tiles from home along the route where it turned, and `dest`. On the way **out** (`dest: 'home'`): the goods go back on the source's shelf at once and the cart is home at `due`. On the way **back** (`dest: 'source'`): the cart carries the goods back and puts them on the source's shelf on `due`. No trip is counted. After `due` the cart is free again (a new trip needs a linked source).
- **The home store is demolished** (or burns down): the cart goes with it; the goods it carries (any state but a return with `dest: 'home'`) go back on the source's shelf at that day's work, to the extent they fit; with the source gone as well, or no room, they are **lost** (event `cartLost`, a caption).
- **The source is demolished:** the goods already left it, so the cart finishes its trip and delivers. A returning cart whose source is gone puts its goods on the home's shelf instead (lost only if the home is gone too).
- **The home has less room on arrival** than when it set out: what fits is put down, the rest goes back to the source (else lost).
- An order taken off mid-trip: the cart finishes and delivers. A demolish taken back (undo) before the next day's work changes nothing (nothing is evaluated until the day's work).

**Tallies and first.** `cartTrips` +1 and `cartGoods` +n when a cart puts goods down at home (a cart whose goods all went back counts none). `first_cart_trip` ("The first cart home", tally `cartTrips` >= 1) shows on the first store with an order. Events (for captions or drawing): `cartHome` { id, good, amount }, `cartTurned` { id, good, amount }, `cartLost` { id, good, amount } (createUI shows only `cartLost`, as an info caption, `S47_CARTS_TEXT.lost`).
