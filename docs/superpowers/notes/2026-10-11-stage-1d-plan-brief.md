## Decisions
- **Save envelope.** A save is `{ version: 1, savedAt: <ms since epoch>, lastSpeed: 1|2|3, world }`; the world inside is `serialize(world)` and stays deterministic (no wall clock in the sim). `src/save/store.js` keeps three IndexedDB records (`staging`, `current`, `backup`) in one object store, with a `localStorage` fallback holding the same three keys. Writes go staging → validate → current, previous current → backup. Loading tries current, then backup only for `corrupt_save`; `newer_version` is refused without touching anything; `not_a_save`/`no_migration_*`/`bad_migration_*` are reported as corrupt to the player ("This save can't be read") but logged with their code.
- **World shape change before the first publish (1a rule: no version bump needed yet).** `createWorld` gains `startRoad` (the generator's tiles), `goals: { completed: [] }` and `history: []` (one `{ day, people, gold, mood }` per month end, newest last, at most 12). `REQUIRED` grows to match. `validateWorld` also rejects unknown building types and `occ` entries that point at missing buildings (1a note). `migrate` guards overshoot.
- **Goals are data plus a daily sim check.** `src/data/goals.js` lists the opening chain (road, 6 plots, well, farm + granary + bazaar, temple, 100 people) then the milestone goal (150 people → Town); each goal has `id`, `text`, `reward` (25 gold), a pure `check(world)` and a `showMe` hint (`category`, `item`, `target: 'startRoad' | 'focus' | 'houses'`). `src/sim/goals.js` `checkGoals(world, events)` runs in `tickDay`, completes at most one goal per day in order, pays the reward and pushes `{ type: 'goal', id, reward }`. Up to three open goals are shown.
- **Month event.** `runMonth` pushes `{ type: 'month' }` and appends the history row; the UI autosaves on it and on page hidden.
- **Goals UI.** A one-line strip under the top bar (below banner and legend) shows the first open goal with **Show me** and a chevron that opens a `goals` sheet (up to three, each with Show me). Show me picks the goal's category and card (the tool starts in placing mode when it names an item) and pulses the target tiles for a second (the start road's inner end, the camera focus, or the existing homes). The summary sheet's goals section lists them too.
- **Boot in two phases.** `main.js` first shows the title card over a paused sample city (fixed seed 11) that drifts slowly (reduced motion: static): Continue (when a save loads), New city, Play with sound / Play muted (writes the sound setting), Install (Android/desktop `beforeinstallprompt`; iOS opens the install guide). Then `startGame(world, { lastSpeed, fromSave })` builds the real UI; Continue opens the **Welcome back** sheet first (date, time since `savedAt`, trends from `history`, open goals, alerts with View, **Carry on** restores `lastSpeed`). New city with an existing save asks and offers Export first.
- **Export/import.** Export shares a `thebes-city-<date>.json` file through `navigator.share` with files when `canShare` says so, else downloads it. Import takes a file from an `<input type="file">`, reads it, `deserialize`s, and replaces the game (a fresh `startGame`, never `Object.assign` into the live world).
- **Install flow and notices.** `src/save/installFlow.js` detects iOS Safari vs home-screen (standalone) vs in-app browsers (Messenger, Instagram, Facebook, LinkedIn, Twitter UAs) with injectable `ua`/`standalone`. First launch in iOS Safari with no save shows the install guide (Share → Add to Home Screen) before a city exists; installed with no save offers "Bring a city from Safari" (import). In-app browsers get a persistent "Open in Safari/Chrome to keep your city" notice. `navigator.storage.persist()` is requested after the first save. A failing save raises a `save_failed` critical alert (spec 6.3) through the existing banner.
- **PWA.** `manifest.webmanifest`, icons (192, 512, 512 maskable, 180 apple-touch-icon, 32 favicon) and the 1200×630 `og-image.png` are rendered by the art code through `tools/assets.html` driven by `tools/render-assets.ps1` (headless Edge; `tests/serve.py` gains a `POST /__file` that writes an allow-listed file), and committed. `sw.js` caches every file listed in `sw-files.js` (generated by `tools/sw-files.ps1`), cache-first, versioned by `APP_VERSION`; a waiting worker shows the "Update ready" toast only when no tool is active; its action saves, tells the worker to skip waiting and reloads.
- **Sound and haptics.** `src/audio/sfx.js` synthesises seven effects (place, road, demolish, upgrade, milestone, alert, goal) with Web Audio, off by default, unlocked on the first user gesture, `navigator.audioSession.type = 'ambient'` when present, no silent-switch hack; `vibrate` pulses on ✓ and milestones when the setting allows.
- **1c carry-overs taken here** (cheap, from `2026-10-10-stage-1c-followups.md`): left-handed mirroring of the confirm bar and rail; Esc closes an open tray or drawer; sheets restore focus by class; legend labels stay readable under a banner (sr-only); effects read reduced motion live; `bazaar_empty` fix text; summary strings into `T`; sprite cache cleared when dpr changes; `tests/serve.py` bind argument for phone testing. Everything else stays in the follow-ups note.
- **Publish.** The plan ends with publish preparation (README, `.nojekyll`, relative paths for the `/thebes/` subpath, a final play-test and screenshots). Creating the public repo and enabling Pages are Josh's call: the controller stops and asks.
