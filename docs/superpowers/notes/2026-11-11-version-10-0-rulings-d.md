# Version 10.0, Track D (the desktop scale): rulings 2120-2129

2120. **Auto is `textSize: null`; `settings.get().textSize` is the size in use.** `DEFAULT_SETTINGS.textSize` is `null`. `createSettings` takes `env()` ({ width, finePointer, coarsePointer }) and `watchEnv(cb)`; `boot.js` hands it the window's (one line, Track F's file: `windowEnv(win)`, `watchWindowSize`). With no `env` (a test's own settings, `createUI`'s own) Auto is 100%, so no existing test changes size. `get()` returns the stored values with `textSize` replaced by the number in use (100/125/150/200), so every reader (`textSize >= 125`, `dataset.textSize`) is right for Auto; the player's choice is `get().textSizeChoice` (non-enumerable, so the key list is DEFAULT_SETTINGS'). The plan said a stored 100 counts as a choice only if the key is there; since 9.x saved the whole settings object, a device that ever saved settings has `textSize: 100` stored and stays at 100% until the player picks Auto (the first Options button). Cost if wrong: an existing desktop player does not see the larger UI by itself. Pointers: `(pointer: fine)` and no `(any-pointer: coarse)`.
2121. **A resize listener was missing; it is added.** Nothing re-applied `--ui-scale` on a resize (a text size never depended on the width). `createSettings` now listens (window `resize`) when it has an `env`; when Auto's size changes (the window crosses 1600 or 2200 px) it re-applies `dataset.textSize` and tells subscribers; a choice never moves; `destroy()` unlistens.
2122. **CSS.** `body[data-layout="wide"]` carries `--panel-w: max(320px, min(320px * scale, 40vw))`, `--drawer-w: 268px * scale`, `--minimap-s: 160px * scale`; the phone layouts keep 320/268 at every text size (a chosen 150% on a phone does not widen the drawer: that would change the phone tests). The 40vw cap keeps a narrow window at 150% a map; the 320 floor keeps 100% exactly as it was, even in a test window narrower than its shell. The wide title card is `440px + (scale - 1) * 480px` (440 at 100%, 560 at 125%, 680 at 150%), and its two-part panel-open form `880px * scale`, both capped at 100% (`css/v82-g.css`, where the wide title rules live; ruling 1673 closed).
2123. **The panel's minimap** is the same 160 canvas px, sized by CSS (`createMinimap` gained `cssSize`, `'var(--minimap-s, 160px)'`), so at 125% and 150% the browser stretches the picture (a little soft); the picture is not rebuilt at a bigger size because that would change the 100% pixels. The sheet's minimap (phone) is untouched.
2124. **The sheet's inset** on the wide layout was the constant 320; it is now the panel's measured width, so a selected building pans clear of a scaled panel.
2125. **The date.** On the wide bar the long form (1000 px and wider, under 150% text) is `Y2 · M9 · D1` (`compactDateText`, `text.js` Track D header); the short form (`Yr 2 Mo 1`) and the phone's `M9` are as they were; the name, aria-label and explainer heading keep "Year 2, month 9, day 1". `tests/ui/hud.test.js` expected the old long form and now expects the new.
2126. **Old tests updated** for ruling 2120: `tests/ui/settings.test.js` and `tests/ui/menu.test.js` compare `get()` with `{ ...DEFAULT_SETTINGS, textSize: 100 }` (Auto with no window).
2127. **Phone sizes cannot change.** Auto needs width >= 1600 and a fine pointer; the phone frame sizes (390x844, 375x667, 844x390, 667x375) are under it even with a fine pointer (a test pins 100% and 320/268 there, and that a chosen 150% leaves them).
