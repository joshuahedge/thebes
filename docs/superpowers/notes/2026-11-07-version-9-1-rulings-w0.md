# Version 9.1 "First hours": rulings 1650-1654 (wave 0, the shared pieces)

The seams src/render/loop.js `createGameLoop`'s `onError`, src/ui/v91/rescue.js `installRescue` (called from src/boot.js), src/ui/createUI.js `blocked()` and `setAutosaveBlocked`, src/render/renderer.js `cacheBytes` behind `window.__thebes.caches()` (src/boot.js), src/sim/progression.js `isUnlocked`'s `world.lessonCards`; index.html's three marked blocks and css/v91.css linked last; the five headers at the end of src/ui/text.js. Tests: tests/v91/w0/ (aggregators tests/v91/all.js and tests/v91/{w0,f,r,a,p,h,balance,docs}/all.js, imported from tests/all.js after tests/v90/all.js).

1650. This release sits before the decree as 9.1 "First hours"; the decree becomes 9.2. — Cost if wrong: renames only.
1651. Wave 0 adds the seams, each a stub with 9.0's behaviour: `createGameLoop({ ..., onError = null })` (given, a throw in a day's tick calls `onError({ where: 'tick', error })` and ends that frame with no more days, no events delivered and no draw, the backlog dropped; a throw in the render calls `onError({ where: 'render', error })`; the loop never stops itself, and without `onError` a throw leaves the frame exactly as on 9.0); `installRescue(ctx)` installs nothing and is called once by `boot`, before the title or a development flag's game opens, with `{ win, doc, root, store, settings, records, io, hooks, game: () => current }`; `createUI`'s `autosave` asks `blocked()` first, which reads a per-interface flag (so per city) that only `ui.setAutosaveBlocked(flag)` sets, false until Track R sets it; a blocked autosave calls no save and raises no save-failing banner (the update's Restart saves through `hooks.save('update')` directly, outside `autosave`, so Track R blocks that one too); `window.__thebes.caches()` returns `renderer.cacheBytes()`, `{ terrainBytes: 0, spriteBytes: 0 }` until Track P fills it in renderer.js (the one renderer the title and every game share), so P never edits boot.js; `isUnlocked` counts a type in `world.lessonCards` as unlocked, after the one-great-temple rule and before rank and prestige; index.html's `<!-- v91 loading -->` and `<!-- v91 early-error -->` blocks (each closed by `<!-- end v91 ... -->`) sit in the head before the first stylesheet and `<!-- v91 preload -->` after css/v91.css, the last stylesheet; text.js's sections F, R, A, P, H in merge order. — Cost if wrong: none to the game; a track that needs a seam shaped differently changes it in its own file and says so.
1652. `world.lessonCards` is optional (absent: none), so there is no world-version bump. The save writes the world whole (`serialize` is `JSON.stringify`) and neither the migration nor `validateWorld` drops a field it does not know, so the list survives a save and a reload with no save change; `validateWorld` does not check its shape and `isUnlocked` ignores anything but an array. — Cost if wrong: one migration later if it becomes required; a hand-edited save with a bad list loads and unlocks nothing extra.
1653. The profile (`tools/profile.ps1`) measures outside the suite; only in-page counters and the lesson's waits are suite tests. — Cost if wrong: a throttled regression is seen only when the profile is run.
1654. A 9.0 lesson city already adopted at Market town is loaded unchanged. — Cost if wrong: a few players keep the old hand-over's rank.
