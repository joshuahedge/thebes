# Version 9.3, the speed fix (rulings 1940-1944)

One line each, with the cost if wrong.

- **1940. The slot is answered from caches.** `lookOfBuilding` (looks.js) keeps each building's look in a WeakMap per world, thrown away when the world's rank, day, `splits.town/city/capital` or buildings version moves (the work is `lookOfBuildingFresh`, unchanged); `slotFor` (registry.js) takes its `<base>.v<v>.l<look>.<state>` and `.far` names, and `house.t<n>`, from tables built once. Cost if wrong: a look that changed without one of those inputs moving would show late (every input the old code read is in the key); a few hundred strings held for good.
- **1941. The other per-frame allocation.** `collectObjects` passes two shared options objects, not one a building; `watchLooks` skips tree and walker ids (1e6 and up). Scaffolds, the sweep and ambient allocate only while a scaffold stands or a ring spreads, and were left. Cost if wrong: none seen; those draw only on a rank-up.
- **1942. The proof and the measure.** `slotForFresh` keeps the old way; `tests/v93/x/speed.test.js` holds `slotFor` to it over the stress city, a Capital and a mid-rebuild Capital across six months of days, staffing, pauses and a rank change, near and far, with and without a world. Speed: the 112 map (Capital and mid-rebuild, desktop DPR 1 and 2, phone DPR 2), 600 frames, 9.3 against 9.2 in a worktree at main, alternating, the lower of two, the load read each run; no frame bound moved. Cost if wrong: a noisy machine hides a gap.
- **1943. The front's centre ignores later building (M1).** `lookCentre` takes the centre and reach from the buildings standing on the rank day (`b.day <= splits[rank]`, or no `day`); its key includes the rank and its day. The look cache's key already holds day, rank, splits and the buildings version, so a cached look refreshes as the front passes on game days. Cost if wrong: a city whose buildings all carry later days has no centre but the palace's or the origin's.
- **1944. Touch with no memory figure is a phone (P1).** `deviceKind` returns phone when `maxTouchPoints > 0` and there is no `deviceMemory` (Safari: every iPad and iPhone). Cost if wrong: a Safari desktop with a touch screen gets the smaller budgets.
