Done as `lessonRoadStep(world)` in `src/ui/placement.js` (`world.lesson && !stepDone(world, LESSON_STEPS[0])`), applied to the idle bar note only, so "Water: bridge up to 4 tiles (25 a tile), ferry 5 to 12" is gone from the first step's bar and the one instruction ("Tap where it starts") stays; the next lesson steps and every ordinary city keep the line. - **2301 (C12, a double tap zooms without selecting).** The plan: the tap handler waits the double-tap window before selecting "when zoom is on". Done in `src/ui/input.js` (`tapWait`, `waitsFor`, an injectable timer): a finger's or pen's tap that would select a building is held for `DOUBLE_TAP_MS` (300 ms), counted at once if a drag or pinch starts or a second tap lands elsewhere (in order), and dropped if it is the first of a double tap. The wait is narrower than the plan's so a single tap never feels slow where zoom is off: a mouse click, any tap while a tool is open (zoom on double tap is off there), a tap on bare ground and a tap while picking a store are instant (`createUI` passes `waitsFor`: a building under the finger and not picking). It is a createUI option, 0 by default; `boot.js` passes `DOUBLE_TAP_MS`, so the rigs (`rigUI` and the older tests that tap by touch and read the selection at once) are unchanged and the real game waits. Cost if wrong: a touch select on a building is 300 ms later; a marker tap is instant.

The sheets and the rest of the page keep the deliberate pinch (ruling 1829) and the viewport meta's `maximum-scale=2` stays. `tests/v81/d/noZoom.test.js` is amended: the four bars read `pan-x pan-y`, the sheet and dialog still `manipulation`. Cost if wrong: only a real iPhone can say; a pinch on a bar no longer zooms the page (the sheet or Options text size is the way).
